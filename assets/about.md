# About This Book

This guide is for developers with roughly 3 to 5 years of experience who already use JavaScript daily and now need to **explain how it works**: the questions product-company interviews ask under the heading "why does this print that?" and "implement it yourself".

## How each chapter is laid out

| Part | What you get |
|---|---|
| 1. Definition | One line, plus why interviewers ask it |
| 2. Core concept | Plain language first, then the precise technical version |
| 3. Internals | What the engine does, step by step |
| 4. Diagrams | Flowcharts and memory layouts, each with a short script for explaining it aloud |
| 5. Code | Small runnable examples with the output and the reason for it |
| 6. Gotchas | The mistakes that cost marks |
| 7. Cheat sheet | A recap you can reread in two minutes |
| 8. Interview questions | Conceptual, output prediction, implement-it-yourself and follow-up traps |

## Reading the notation

- **★** marks a question that is very frequently reported by candidates.
- **Easy / Medium / Hard** is the difficulty at the 3 to 5 year level.
- **Model answer** boxes are written to be said aloud in 30 to 60 seconds.
- **How to explain this to the interviewer** boxes tell you what to draw first, what to point at, and the one-sentence takeaway.
- **Whiteboard version** figures are small enough to draw in under two minutes.
- Diagrams use labels and line styles, never colour alone, so they survive black-and-white printing.

## Where the content comes from

Technical statements follow the ECMAScript specification, MDN, javascript.info, *You Don't Know JS* (Kyle Simpson), Jake Archibald's event-loop material and the V8 blog. Every code sample was executed on Node.js 22 (V8) and the printed output is what that run produced. Where browsers differ from Node.js, the text says so.

Interview questions are selected from experiences that candidates have shared publicly (blog posts, community forums and question collections). A question is marked ★ when it recurs across many such sources. Where a source could not be pinned down, the question is labelled *commonly reported* rather than attributed to a company, and no quotes or company names are invented.
